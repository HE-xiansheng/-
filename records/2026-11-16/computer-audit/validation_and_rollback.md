# 分阶段验证与回退

用户已确认电脑下载目录存在完整恢复备份镜像，系统准备直接沿用，不再要求重复制作。该信息来自用户确认，尚未独立完成文件定位或恢复验证。

本文件是实施与验收计划。除 S0 中明确列出的审计工作外，各阶段尚未执行。所有真实飞控验证均保持未解锁，不触发模式切换、任务、起飞或降落命令；任务逻辑先使用录制输入和模拟接口验证。

## 目录与运行边界

- 已有 `~/drone_platform/`、ROS1 安装空间、systemd 服务和地面站入口保持原样。后续建议另建 `~/ros2_migration/{src,config,locks,experiments,results}`，不同目标的 build/install/log 分开存放；本轮尚未创建该远端目录。
- 目标为原生Ubuntu22.04 ARM64与ROS2 Humble。先准备5 Ultra专用Jammy镜像、独立启动介质、恢复备份和依赖清单；写盘、切换启动介质或停现有服务前说明影响并由用户确认。容器仅在有实际需要时辅助离线回放/桥接，不是必经部署方式。
- 回放/算法输出使用独立 ROS_DOMAIN_ID 与 `/migration_test` 名称空间。Domain 隔离不能阻止同一环境直接使用串口、UDP 或 SSH，测试环境同时不映射真实飞控串口、不放行任务 SSH 入口，控制输出接到记录器或模拟端。
- 离线阶段不访问 Livox 实时端口、相机、NPU 和云台控制端口。硬件阶段逐项开放；同一雷达、相机或飞控不可由两套驱动竞争占用。需要停止现有服务或释放设备时，先说明对象、影响、时间和恢复步骤，由用户确认后执行。
- 所有实验固定输入、配置、消息定义和版本。源码中的默认值不替代现场有效配置；使用源时间戳测率与延迟，使用单调时钟判断超时。

## 每阶段统一交付

每次实验建立独立目录，至少保存：

| 文件 | 内容 |
|---|---|
| `experiment.yaml` | 阶段、编号、日期/时区、主机与 boot ID、目标、输入路径和 SHA256、设备访问范围 |
| `repos.lock.yaml` / commit | 源仓库和 commit、submodule、现场补丁；不能把无 Git 的部署包臆定为上游版本 |
| `environment.txt` | OS/BSP/内核、架构、编译器、ROS/RMW/DDS、deb、容器 digest、SDK/运行库/模型/固件 |
| `config/` | launch 与节点参数、话题与 QoS、TF/外参、时钟策略；真实飞控参数在任何变更前另存只读基线 |
| `observations/` | rosbag/rosbag2、必要图像与日志、状态与性能统计；标明记录时是否包含控制输出 |
| `result.md` | 实际执行项、通过/失败/未验证、测量窗口与限制、和 ROS1 对照结果 |
| `issues.md` | 新问题、复现输入、负责人/后续动作、影响的阶段 |
| `rollback.md` | 新增进程/文件、恢复入口、需要用户确认的操作和恢复后检查 |

只有对应的行为验收通过，才能标记该模块完成迁移。编译通过、话题已注册、GUI 有数值、飞控本地位姿在发布，都不能单独作为通过依据。

## S1：原生22.04测试环境与接口构建

镜像/介质/恢复准备详见 [22.04原生路线](ubuntu22_native_plan.md)。

顺序：准备并核验5 Ultra专用Ubuntu22.04镜像/备份 → 经用户确认后在独立介质安装和启动 → 验证BSP基础设备 → 安装锁定的Humble环境 → 迁移消息包 → 基础节点/参数/launch → 只接录制输入的适配器。用户已选择最终安装到eMMC，SD作安装介质；旧系统和ROS1基线沿用已有恢复镜像与源码资料；先查明转发源码对应关系，不把旧Noetic的setup或生成绑定直接source到新系统。

验收：

- 能从锁定清单重建；不 source 进 ROS1 生产服务，环境中无 ROS1/ROS2 生成消息串用。
- Livox 单点时间、EGO 轨迹字段、MAVROS 字段/常量逐项核对；`Header.seq` 用独立标识承接。
- 测试消息可在两个独立进程之间收发，QoS 显式记录；可靠/尽力、持久化、晚加入行为符合接口要求。
- 参数已显式声明与加载；错误配置能被发现。namespace、节点私有参数与 remap 的解析结果明确。

回退：只停止新增环境，保留其日志；生产服务不受影响。修改源码通过独立仓库的 commit 回退，不覆盖旧工程。

## S2：传感器数据读取

先用现有数据回放验证解析，再安排真实设备窗口。真实设备窗口如需释放 ROS1 驱动，先征得用户确认。保留相机固件 1.4.60；若必须升级，应另列固件支持、能否降级及校准影响。

验收：

- Livox 保留 `timebase/offset_time`、点类型、线号及 IMU 单位；对照现场约 10 Hz/200 Hz 的短时基线，另测持续运行、丢帧、乱序、时钟漂移。建议连续采样至少 5 分钟，后续按实际负载延长。
- Gemini 彩色、深度、左右 IR 与 CameraInfo 均有有效数据，尺寸/编码/光学帧正确；验证深度尺度、对齐方式、同步、USB3 带宽和标准订阅启流。当前三帧证据不能替代这些持续验收。
- RTSP 首帧、延迟、断流恢复、MPP/RGA 使用及 CPU 负载可复现；RKNN 模型/Runtime/驱动实际加载链正确。
- TF 和标定数据完整可读；每条输入有源时间戳、来源、帧和单位说明。

回退：停止新增驱动，按已获确认的恢复步骤恢复原服务和设备占用，再确认 ROS1 点云/IMU/图像重新正常。不得同时重启两套采集来试错。

## S3：定位与位姿转发

先固定同一份原始点云/IMU录包，对照 ROS1 与 ROS2，输出到独立测试话题。需要补录或启动当前停用的 ROS1 定位时，先说明资源与输出范围；不能由带控制逻辑的总启动脚本间接启动。

验收：

- 沿用 `fast_lio/config/lidar.yaml` 的有效配置；软件同步、IMU 加速度尺度、点时间单位与初始化可解释。
- 轨迹、姿态、body 线速度和去畸变点云对照，检查启动、转向、平移、静止、重定位/重启、输入中断与时间跳变。定位精度阈值需要用实际场地和现有系统基线确定，当前没有精度测量，不能预填“厘米级通过”。
- `camera_init→body` 与 FC `map/base_link` 的原点、旋转、偏移由明确变换定义；`/factory_fastlio/tf` 隔离按设计保留。相同数据经转换后方向/量值正确。
- 转发同时统计输出频率、独立源戳数、重复/过期数据、源到发送延迟和最长间隔。明确旧二进制的缓存行为；ROS2 节点拒绝无效观测，不伪造源戳。
- 断流、退初始化、重启与多发布者情况下不会继续把旧数据当新定位。MAVROS2 的可靠订阅和同戳去重已有针对性验证。

回退：测试仅写独立话题时停止新增节点即可；如曾获准切换真实定位输入，先停新输入，再恢复原单一输入源与原配置，并复查有效数据和飞控估计器状态。

## S4：飞控接收与融合的地面验证

旧20.04基线保留MAVROS1；新22.04测试环境采用Humble对应MAVROS2，真实串口接入另列窗口。只有确有逐步过渡需要时才增加受限bridge环境，不要求原生22.04直接运行旧Noetic安装空间。更换MAVROS进程、定位正式输入或飞控参数均先说明影响，由用户确认。不升级PX4固件。

验收：

- 只读确认当前实际固件和 EV 参数；记录 MAVROS 和 PX4 时间同步、外部估计消息实际到达与样本间隔。`vision_pose` 接口不带速度，不把 `EKF2_EV_CTRL=15` 当作四项均有测量输入。
- 真实飞控保持未解锁、不改变飞行模式。地面观察 EKF 融合标志、创新/拒绝状态、外部定位原点及高度/航向一致性；如缺少可读指标，先列为未验证，不用本地位姿输出代替。
- 在先完成隔离实验并获得相应现场确认后，检查输入中断/恢复、时间倒退及大跳变的响应。任何需要运动或飞行才能证明的性能仍标明未验证。
- 无两个 MAVROS 竞争串口，无两个定位源写同一正式输入。首轮不桥接解锁、模式或高频 setpoint。

回退：只在已获准窗口恢复原 MAVROS 服务/原定位路径；若有用户批准的参数变更，逐项核对后恢复原值。回退后检查连接、未解锁、传感器数据与估计器状态；不能在任务运行中直接“热切换”。

## S5：规划、航点和视觉任务

使用录制输入、mock MAVROS/任务接口与隔离的仿真环境，真实串口和任务 SSH 路径不可达。不因参数名叫 `prepare`、`dry_run` 或 `bench_mode` 就认定无控制输出；先检查启动后会发布/调用什么。

验收：

- EGO：相同地图/状态下的避障、轨迹连续性、重规划耗时、body 速度解释正确；候选与确认绑定会话，重复/旧确认、换目标、接管、停止、输入中断不会执行旧轨迹。
- 航点：准备、RC 边沿、航点/拍照、返航/降落、超时/接管的状态迁移由模拟事件验证；保留当前 version4 协议与实际自动起飞/返航/降落设置，不在真实系统触发。
- ArUco：已知码尺寸/距离/方向、标定分辨率、同帧 ID/Pose/metrics、源戳/接收戳和光学坐标可核查；无目标、错误码、旧图与丢帧行为正确。
- 精准降落与跟踪：控制方向、限速/高度、丢目标、RC 接管、互斥和停止均通过模拟输出检查。异步服务完成不能在任务取消后重新激活控制。
- RKNN：同模型同输入的检测输出、RGB/深度配对、目标选择、端到端延迟和 NPU 负载有对照。保持实际 Runtime2.3.2，不能误用系统1.4.0。

回退：停止新增测试进程，归档结果并恢复测试 commit。未经用户后续明确授权，不将通过模拟验证的控制器接到真实飞控执行任务。
