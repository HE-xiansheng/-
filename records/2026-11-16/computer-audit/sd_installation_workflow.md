## 本次卡片只读盘点

详见 `raw/sd_card_inventory.json`，当前发现值如下；后续写卡前须重新识别，不能把盘符固定为脚本默认值。

| 属性 | 本次读取结果 |
|---|---|
| 设备 | `/dev/sda`，USB读卡器，可移动 |
| 读卡器型号/序列标识 | MassStorageClass；Generic_MassStorageClass_000000001536-0:0。此为读卡器标识，不等同于SD本身CID |
| 实际容量 | 62,534,975,488字节，约58.2GiB |
| 分区与挂载 | `/dev/sda1`，exFAT，UUID34D6-6B9D，挂载于`/media/tyzk/34D6-6B9D` |
| 可见内容 | 已列出根目录，当前为空；不据此声称卡上从未有过数据 |
| 电脑系统盘 | NVMe设备，当前根分区`/dev/nvme0n1p8`，不属于写卡目标 |

历史案例的eMMC用户区为62,579,015,680字节，比本卡多44,040,192字节（42MiB）。因此不能因为都标称64G，就将旧eMMC整盘原样克隆到这张卡。现有恢复备份继续保留在电脑；本卡应写较小的专用Jammy系统镜像，并在启动后按实际分区扩容。

|---|---|
| 设备身份与容量核对 | 原样保留原则：盘符、读卡器/by-id、字节数、分区/挂载和已有数据用途交叉核对；插拔后重新识别 |
| 板型、镜像来源与版本 | 保留来源、板型和字节数检查；用户已要求跳过额外完整性测试。只选Orange Pi 5 Ultra专用Jammy/ARM64，先核实来源、校验来源及解压后长度；历史Debian救援系统不作为本次镜像 |
| 写卡前卸载、写入同步与读回 | 必须保留。获准覆盖具体卡后卸载其全部分区，按整盘镜像的分区表写整卡，不是复制img文件到exFAT。按用户最新要求不做全盘读回或整文件哈希，保留写入返回值、字节计数与同步结果 |

| 分区扩展与首次启动 | 复用检查方法，不复制历史分区号。优先使用该Jammy镜像自带初始化/扩容；任何离线扩容前核对真实结构并卸载 |
| 同步、正常卸载与安全弹出 | 保留；写入及同步成功后才弹出。机载换卡/换启动环境前按用户要求另确认，正常关机后插拔 |
| 分阶段状态与实测 | 保留：下载完成、压缩校验、解压长度、写后读回、离线配置、上机启动、网络SSH、设备/驱动、ROS2功能分别记录，不能把能启动当作平台完成 |

## 本次不照搬的内容

- 不清理原Ubuntu20.04的日志、machine-id、网络绑定、SSH或Tailscale身份，不删除飞行记录和工程。
- 不重复制作用户已有完整恢复镜像；不安装`capture_emmc.py`或自动采集服务，不让插卡上电后自动备份或恢复eMMC。
- 历史成功案例的`Armbian...trixie...6.1.172...img.xz`是Debian Trixie救援镜像，不是Ubuntu22.04。
- 不设置旧救援卡的root/root凭据，不直接套Armbian的首次登录标记、服务名或单ext4分区布局到厂商Ubuntu镜像。
- 旧流程末尾“删临时网络/密钥、关闭SSH”是离线救援卡收尾。本次SD是Ubuntu22.04启动/安装系统，应在安装和验证期间保留正常管理通道。
- 不把旧完整恢复镜像恢复到本卡来冒充22.04，eMMC现已选为最终安装目标，具体覆盖待说明影响并确认；不顺带写SPI或boot0/boot1。

用户已明确选择eMMC安装、SD仅作启动和安装。实际安装流程见 [eMMC安装方案](emmc_install_plan.md)，下方保留制卡准备细节。

## 本次建议顺序

1. 选择并记录5 Ultra专用Ubuntu22.04 Jammy镜像，优先评估厂商5.10版本；校验实际驱动包和来源，6.1作为有官方依据的候选。
2. 下载至电脑独立目录，保存来源、SHA256与原始字节数，校验压缩完整性和能否放入本卡。此处尚未确定具体镜像文件或开始下载。
3. 提交具体写入对象/容量/数据覆盖范围及镜像校验结果；确认可覆盖这张卡后才执行整盘写入与读回。技能明确要求“写卡前确定具体介质及已有数据用途”；本轮只请求参考步骤，因此当前无需发起写盘确认。
4. 离线核对系统版本/板型与启动文件，配置实际网络/SSH，确认账号与权限，按该镜像机制处理首次启动和扩容；同步、安全卸载。
5. 列出从当前eMMC系统切到SD的影响，确认后正常关机、插卡启动。先实测系统根分区确实位于SD，不能只凭插卡就认定已从SD启动；不改SPI来强行改变启动顺序。
6. 验证网络、USB、Livox、Gemini335L、rknpu/RKNN和MPP/RGA，再安装Humble并按原迁移验收逐模块推进。全程不自动启动飞行任务、解锁或起飞。

后续实际写盘、切换机载启动环境和正式环境前，仍遵守用户原有确认边界；当前不会因此停止旧服务或触碰原系统。
