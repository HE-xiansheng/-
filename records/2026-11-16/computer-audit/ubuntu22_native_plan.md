# Ubuntu22.04 原生迁移路线

用户已确定使用Ubuntu22.04，当前目标为**Orange Pi 5 Ultra专用Ubuntu22.04 ARM64 + ROS2 Humble**。这取代最初的Jazzy用户态建议；系统尚未重装，ROS2尚未安装。用户随后确认电脑下载目录已有完整恢复备份镜像，直接沿用，不再重复制作。文件路径/校验信息尚未在本轮独立确认，不影响继续准备新系统方案。

当前部署选择：**Ubuntu22.04最终安装到eMMC；SD只用于启动和安装**。不要求保留原20.04可启动介质，已有完整恢复镜像仅作故障时备用。具体流程见 [eMMC安装方案](emmc_install_plan.md)。

## 系统与版本选择

| 项目 | 决定与验证要求 |
|---|---|
| 系统 | 5 Ultra专用Jammy镜像，不能用普通PC镜像或其他Orange Pi型号镜像代替 |
| 内核/BSP | 官方wiki同时列5.10与6.1；优先评估接近当前5.10的Jammy镜像。镜像内实际rknpu、USB、MPP/RGA仍要核实，不把同内核大版本当成ABI相同 |
| ROS | Humble，官方支持Ubuntu22.04 ARM64；官方支持至2027-05，后续维护需保留版本锁定与构建资料 |
| 定位/规划 | 官方FAST-LIO ROS2分支和EGO ros2_version分支均有Humble参考；保留现场速度补丁、配置与业务扩展 |
| 飞控 | Humble对应MAVROS2，继续MAVLink/USB与当前PX4；本次Humble rosdistro索引为2.17.0-1，实际安装时锁版本 |
| 推理/媒体 | 保留RKNN模型与Runtime2.3.2的来源/摘要，对照rknpu0.9.6基线；新镜像实际驱动组合与MPP/RGA须验证，不自动覆盖系统库 |
| 相机 | 保留Gemini335L固件1.4.60，选择验证过的Humble wrapper/SDK组合；不得为迁移自动刷固件 |

官方依据：已保存的 `official/orangepi-ultra.html` 中“Supported Linux image types and kernel versions”列Jammy5.10/6.1；随后兼容表列USB、网络、NPU、VPU等。官方构建配置也列jammy。具体镜像文件、下载来源、校验值和打包驱动版本尚未确定，不能声称已有镜像通过本机验证。

## 系统准备与实施次序

1. **恢复准备。** 当前根盘为`/dev/mmcblk1p2`，同盘`p1`为/boot，另见16MiB的mtd设备。先核实介质身份、启动链和可用独立介质，不靠设备编号猜测写盘目标。用户已有完整恢复镜像，沿用该镜像作为恢复基线；本审计的文本快照仅作源码/配置对照。后续实际写盘前核对现有镜像路径、校验记录及恢复对象，不重复制作备份。
2. **锁定镜像。** 核对确为5 Ultra、Jammy/ARM64及内核，取得可信下载来源与校验值，记录bootloader/DTB、rknpu/Runtime、MPP/RGA版本。SD用于引导和存放安装镜像；eMMC覆盖范围经说明并获确认后安装，不自动写SPI或改boot0/boot1。
3. **独立介质验证。** 列明写入目标、数据覆盖范围、停机/启动影响和恢复步骤，经用户确认后写盘并启动。先验收网络/SSH、USB、雷达、相机、NPU与视频硬解，不立即启用原总服务或任务程序。
4. **独立ROS2工作空间。** 在新系统另建`~/ros2_migration/`，安装/锁定Humble依赖，先迁移自定义消息及回放接口；原`~/drone_platform/`作为保留的ROS1基线，不在其中重新编译覆盖旧产物。
5. **按链路迁移。** 传感器读取→FAST-LIO与位姿转发→MAVROS2接收/融合→EGO及任务逻辑→地面站数据、视频、任务状态及录制回放。验收标准沿用`validation_and_rollback.md`，所有真实飞控验证保持未解锁。

## 保留ROS1与回退

- ROS1工程与旧系统基线由已有完整恢复镜像及审计副本保留，不要求保留旧系统在eMMC继续启动。Noetic官方二进制面向20.04，不能期待新22.04直接source原安装空间即可运行。
- 若需要新旧ROS并行过渡，在独立环境源码构建Noetic/bridge，并只桥必要标准数据和已核对的自定义消息。桥不是必经步骤，不将控制服务和高频setpoint默认双向转发。
- 新系统未通过板卡和关键设备验收，不切换正式运行环境。若安装失败且用户要求恢复，再使用已有恢复镜像；正常流程不自动恢复旧系统。
- 使用现有系统原地`do-release-upgrade`会改变大量底层依赖，不作为此次方案。

目前完成的是版本路线修订与官方依据核实；镜像正在核实与准备；完整恢复备份由用户确认已有，不重复制作；写盘和设备验收尚未执行。
