## 诊断副本与第二版候选

45 秒诊断副本 (`live-probe.json`) 复现失败：位姿最大龄 1.102 秒。保存全部原始回调/解算耗时，三份原始文件已独立 SHA 校验。雷达到达 RMW 后等待回调中位 0.220 秒、最大 1.131 秒；IMU 等待中位 0.091 秒、最大 0.708 秒。解算中位 46.4 ms、95 分位 110.8 ms。25 ms 以上的 span 全部为 timer，未观测到超过 25 ms 的 odometry/world/body 发布调用。这证明本轮至少有独立的 executor 等待，不能把它说成仅仅点云 publish 阻塞；可靠 LiDAR 传输也出现长尾，后续需对照。

第二版候选将两个传感器放在同一个互斥回调组、解算/输出保持默认互斥组，以两个 executor 线程允许输入在解算期间持续接收。`sync_packages` 与输入共用 buffer mutex，完整转移测量组后即释放；`publish_count` 改为原子计数，避免新增并发的数据竞争。传感器间的时钟判断/预处理仍串行，滤波状态与地图只由解算组访问。仍保留 IMU Best Effort/400、可靠 LiDAR/20、原标定与时效。源码/清单为 `candidate-v2-source*`，构建安装只去临时 `install-v2`；尚未通过真实验收，更未部署。初始 install 中 17af 二进制保留，不能使用现在过期的初版安装清单。

第二版实际 run5（Fast DDS）和 run6（仅子进程 Cyclone）均失败，后者参数 RPC 也未完成。详见各轮结果，不能把线程分组或换 RMW 单独宣布为有效修复。run1–6 的24份机载原始文件均已独立 SHA 核对。第三版保留分组与共享缓存保护，将 LiDAR 也改 Best Effort / 20；源码与构建为 `candidate-v3-*`，仍只在临时目录验证。
