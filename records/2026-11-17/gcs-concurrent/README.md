- run3：加入逐秒状态后，失败为云台接收新鲜度，遥测、相机与录制持续正常。云台路径额外经过SSH隧道；改直连独立端口继续对照，不据此宣布产品播放器故障。失败清理分支漏导入shlex，修正前曾提前结束归档；测试进程退出后重新取回完整证据。录制正常STOPPED、两个分包、active清除，但这次是测试清理停止，不能算GUI停止按钮通过。

## rosbag2诊断与候选

本机用仅解包的gdb-multiarch读取ARM64 core及对应机载库，未安装机载调试器/替换系统库。崩溃线程在 `memcmp → Recorder::warn_if_new_qos_for_subscribed_topic → topics_discovery`。官方0.15.17与读取时humble分支的stop()设置stop_discovery后只等待两倍轮询间隔；超时仍清空subscriptions，而发现线程也访问该表。原日志明确出现发现线程等待超时。因此证据支持退出时并发访问的判断；缺少完整调试符号，不能将所有内存细节表述为已证明。

原平台显式`-p 1`实际为1毫秒，退出只等2毫秒，并非1秒。候选恢复官方默认`-p 100`，保留动态发现、QoS覆盖、缓存/分包与停止错误检查。run3已正常收尾；另26项隔离原生录制回归全部通过，包括多次手动/自动起停、缺失话题、分包、终止监督器收尾、未完成录包拒绝覆盖及无控制发布者。它降低本次触发风险，并未修复rosbag2底层超时后继续清表的实现；仍需持续并发验证。
