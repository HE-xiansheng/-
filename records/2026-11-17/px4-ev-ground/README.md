# 实物 PX4 外部视觉接收、融合与时间戳

新机实际 MID360(.158) → 已安装 FAST-LIO → 原位姿转发 → 完整 MAVROS → 实物 PX4 1.16.0。临时 domain187 / localhost；专用串口桥记录双向真实报文，只允许时钟、遥测查询、被动任务下载和新鲜有限的外部视觉位姿。心跳确认实际 PX4 未解锁后才允许转发。禁止模式、解锁、参数写入、设定点和任务上传；未发送飞行或云台动作。

## 结果

| 记录 | 结果与范围 |
| --- | --- |
| run1 | 初始串口半帧/非MAVLink前缀使工具解析失败，尚未转发视觉 |
| run2 | 工具误拒伴随电脑自身 base_mode192 心跳；该消息不是解锁命令 |
| run3 | 工具误拒广播固件版本读取请求；修正规则，保留禁止写入项 |
| run4 | 重新上电期间SSH预检超时，未创建测试目录 |
| run5，75秒 | 初版17/17；643条真实源位姿逐戳到达飞控；独立坐标/姿态6/6 |
| run5独立时间复核 | 所有EKF实例融合通过；早期25/50秒样本时刻映射未收敛，严格时间检查失败，未覆盖此失败 |
| run6，145秒 | 初版17/17；1339条真实位姿；独立坐标6/6和晚期多实例/时间6/6全部通过 |

run6 在100/125秒取得的实际 `vehicle_visual_odometry.timestamp_sample`，减PX4估计时钟偏移后，与串口真实 `VISION_POSITION_ESTIMATE.usec` 相差124/61微秒；位置匹配误差最大6.12微米。PX4保留的接收时间减测量时间为49.884/47.777毫秒，同步RTT为2.498/3.523毫秒。官方1.16 `Timesync::sync_stamp` 在500个有效低RTT样本前回退到接收时刻，因此“已收到timesync消息”不能代替源时刻映射验证。

两个实际 EKF 实例0/1均报告 `cs_ev_pos/hgt/yaw=true`；每个实例对应三种 aid-source 均 `fused=true`、`innovation_rejected=false` 且最近融合时间新鲜。速度融合未启用，此链路只发送位姿。独立ENU/FLU→NED/FRD验证最大位置误差7.53e-10米、姿态角误差5.96e-8弧度；这些是数值转换误差，不是实际定位精度。

## 复核与限制

`tools/analyze_px4_ev_wire.py` 独立重算四元数/坐标；`tools/analyze_px4_ev_sync.py` 按每个 `Instance N` 分块检查，避免初版字段解析覆盖前一实例。工具/PTY的正负检查见 `pty-policy-checks-query.json`。`official-1.16/sources.json` 固定官方Git对象、URL和SHA。

各轮 `evidence.tar.gz` 包含完整原始报文、ROS位姿、NSH只读结果和节点日志。串口配置已恢复，测试进程已退出，机载临时目录在取回后删除。未更改PX4参数、固件、正式服务或产品源码，无永久部署需要撤销。

仅证明静态地面接收和融合，不能证明机体安装外参、运动精度、长期时钟稳定性、飞行安全或实际任务完成。USB相机/云台接入检查另见相邻 `new-physical-cameras`。
